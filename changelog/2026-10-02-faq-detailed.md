# FAQ: реализация и согласованные отличия от ТЗ

2 октября 2026 года. Реализация подготовлена в `madloba.info` для передачи на сервер и проверки заказчиком. Развёртывание на production не выполнено. По последнему указанию Alex синхронизация других движков в эту доставку не входит.

Код и два отчёта доставляются одним общим коммитом. [История коммитов реализации FAQ](https://github.com/hardcodd/new.madloba.info/commits/main/faq/). Точный hash сообщается при передаче: включить собственный окончательный hash в содержимое того же коммита невозможно без изменения его hash.

## Реализация

- Добавлено приложение `faq` с иерархией Home → FaqIndexPage → FaqCategoryPage → FaqQuestionPage. Под главной допускается один индекс, под категорией — вопросы, у вопроса нет дочерних страниц. Группы категорий имеют переводимые названия и порядок.
- Страница вопроса содержит краткий ответ, 2–5 причин, развёрнутые пояснения, совет, исключения, пару «заблуждение / исправление», альтернативные формулировки, источники, даты, важное замечание, обложку, видео, CTA и похожие вопросы. Необязательные пустые секции не показываются. Неполная пара заблуждения и исправления отклоняется отдельно для каждого языка.
- Категория показывает текстовые карточки: вопрос, первое предложение ответа, дату проверки. Сначала популярные, затем недавно проверенные; пагинация по 16 записей использует существующий механизм движка.
- Главная FAQ показывает категории и до шести популярных вопросов. Блок главной сайта вручную размещается в StreamField и поддерживает четыре режима: первая публикация, популярность по редакционному флагу, дата проверки, ручной порядок. Количество ограничено 24.
- Похожие вопросы: пустое поле выбирает четыре публичных вопроса текущей категории по дате проверки, кроме текущего. До пяти ручных ссылок заменяют этот список; очистка возвращает автоматический подбор. Сохраняются ручной порядок и фильтрация публичности/сайта.
- Общая правая колонка содержит категории с активным состоянием и наследуемые связи категории с блогом/каталогом. Закрытые страницы, черновики и другой сайт исключаются. Короткая панель закрепляется под шапкой, слишком высокая остаётся в потоке; внутреннего скролла нет. На телефоне панель статична.
- Форма вопроса разделена на «Ответ», «Пояснения к ответу», «Источники», «Ссылки и медиа», «Продвижение». Переводы используют общий переключатель языков, включая названия вложенных источников. SEO, социальное изображение, популярность и теги находятся в «Продвижении». Встроенные настройки Page сохранены: Wagtail 7 скрывает отдельную вкладку при наличии только PublishingPanel/CommentPanel; расписание доступно через панель статуса и «Установить расписание».
- Поиск FAQ использует общий endpoint с `scope=faq`, ограничен публичными вопросами текущего сайта и сохраняет scope при повторном запросе и пагинации. Общий поиск сохраняет прежнее поведение.
- Серверный HTML содержит весь текст ответа. На телефоне CTA находится сразу после краткого ответа. YouTube iframe создаётся после нажатия, используется youtube-nocookie; URL проверяется при сохранении.
- JSON-LD строится из тех же переведённых полей: FAQPage с кратким ответом и альтернативными формулировками, BreadcrumbList, WebPage с редакционными датами. Защищён выход из script через содержимое. Добавлены FAQ-типы в генератор sitemap, краткий ответ используется как запасное описание, социальное изображение — для предпросмотра ссылок.

## Согласованные отличия и ограничения ТЗ

| Решение | Обоснование и последствия |
| --- | --- |
| Нативная админка и оформление движка | Использованы существующие права, ревизии, редактор и визуальные компоненты. Макет служит ориентиром структуры, отдельная система управления не создаётся. |
| Wagtail ID вместо registry_id Q-0000 | Отдельная система номеров не добавляется. Обновление CSV использует `id`, создание — существующий `parent_id`. |
| Существующий CSV-контракт | Связи и изображения передаются по ID, repeatable-поля — нативным JSON StreamField, rich text — HTML. Отдельные source_1_* колонки, ссылки через registry_id, parent_slug и поиск CTA по полному URL не добавлены. За основу таблицы следует брать экспортированную строку. |
| Обычная языковая политика | Сохранены переводы, fallback, hreflang и sitemap всего движка. Специальное исключение пустых языковых версий только для FAQ не вводится. Языки задаются настройками сайта. |
| Настраиваемые группы | Вместо жёстких семи географических групп редактор задаёт названия и порядок; общий модуль пригоден для других сайтов семейства. |
| Расширенный rich text | Вводные и развёрнутые пояснения используют полный привычный редактор с изображениями и embed. Краткий ответ и формулировки остаются обычным текстом. |
| CTA необязателен | Полный ответ может не иметь отдельного материала; пустая кнопка не выводится. |
| Рекламный флаг исключён | По уточнению Alex рекламные требования попали в ТЗ ошибочно. Отдельный is_grey_topic не добавлен. |
| Типы вопросов и подборки отложены | question_type, его фильтр и отдельные подборки относятся к следующему этапу. Теги сохранены. |
| Поиск включён в первый этап | Реализован существующими средствами, без отдельного поискового сервиса. |
| Один блок главной с четырьмя режимами | Сохраняется ручное управление размещением, отсутствуют четыре дублирующих блока. Популярность задаётся редактором, посещения не подсчитываются. |
| Нет кнопки «Все категории» в sidebar | Все категории уже перечислены, а переход в FAQ есть в хлебных крошках. Кнопка повторяла тот же адрес. Отдельного требования к ней в текстовом ТЗ не найдено; Figma при последней сверке повторно не проверялась. |

## Импорт, безопасность и производительность

CSV-строка обрабатывается в транзакции. Проверяются права редактирования/публикации, ссылки, StreamField, даты и валидация вопроса. `live=false` сохраняет черновик без изменения опубликованного ответа; `live=true` публикует. Существующий pending draft нельзя затереть публикацией из CSV. Заблокированные страницы, workflow, aliases и запланированные ревизии отклоняются. Пустые сопоставленные необязательные поля FAQ очищаются, несопоставленные сохраняются. Экспорт сохраняет структуру блоков, HTML, переводы, теги и ID связей.

Счётчики категорий используют SQL COUNT по родительскому пути Wagtail: приложение получает одну строку на непустую категорию вместо всех путей вопросов. Публичность и сайт учитываются, пустые категории получают ноль. Карточки не загружают длинные переведённые тексты, StreamField и ненужные изображения; краткие ответы и заголовки всех языков остаются доступны без запросов на каждый fallback. Панель не загружает intro и полные specific-модели связанных разделов. Кэш и денормализованные счётчики не добавлены; БД всё равно обрабатывает подходящие записи.

## Миграции и установка

Подготовлены `faq.0001_initial`, `faq.0002_alter_faqcategorypage_intro_and_more`, `home.0006_alter_homepage_content_alter_homepage_content_en_and_more`. Первая создаёт модели FAQ и теги, вторая расширяет rich text с сохранением прежнего обычного текста и черновых ревизий, третья добавляет блок FAQ в переводимые поля главной. Вторая миграция экранирует прежний текст; обратная конвертация удаляет rich-форматирование.

На текущей локальной базе эти миграции применены; `migrate --plan` не показывает ожидающих операций, `makemigrations --check --dry-run` не обнаруживает отсутствующих миграций. Локальная демонстрация содержит 6 категорий и 60 вопросов. Демонстрационные записи не входят в Git и не являются проверенными ответами.

На сервер доставляются готовые миграции из этого репозитория, затем выполняются `migrate --noinput`, обычное обновление поискового индекса и генерация sitemap. На production не выполнялся ни migrate, ни создание FAQ-контента. Истории миграций других сайтов не копировались.

## Проверки

- Полный набор: 287 тестов прошли, включая 39 FAQ-тестов. Отдельно все 287 тестов прошли на изолированном снимке подготовленного индекса Git, без посторонних рабочих файлов. Проверены иерархия, формы, переводы, JSON-LD, публичность, поиск, страницы и блоки, импорт/экспорт, черновики и ошибки.
- На тестовых 1000 вопросах проверены одна агрегированная строка, ограничение популярных карточек и пагинация. Это проверка корректности и объёма возвращаемых данных, а не production-нагрузочный тест.
- Django check, makemigrations --check --dry-run, Ruff изменённого Python и git diff --check прошли.
- В браузере проверены главная, индекс, категория, вопрос, поиск, 375px без горизонтального переполнения, CTA, состояния и закрепление sidebar. Создание iframe по клику подтверждено; тестовый ролик оказался недоступен на стороне YouTube.
- В локальном предпросмотре настоящей формы проверены вкладки и переключение RU/EN, включая источники и сохранение выбора языка между вкладками. Формы дополнительно проверены тестами; ручное сохранение/публикация под рабочей учётной записью остаются частью приёмки.

Остаются установка на сервере, проверка рабочего CSV, действия редактора, разрешённый к встраиванию ролик и подтверждение заказчиком. Production RPS/latency не измерялись. Посторонняя работа сохранена и не включается в коммит FAQ. Синхронизацию остальных сайтов Alex выполнит отдельно после согласования с заказчиком.
